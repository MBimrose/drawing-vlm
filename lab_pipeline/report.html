This document describes the training pipeline. The pipeline makes a model. The model reads an engineering drawing and writes a build123d program. The program makes the part. The pipeline then uses the model to make new training data. This document also gives the results.

The pipeline has one rule: Use only data that a test has approved. This rule caused each gain in the strip above. The mean IoU on the test set increased from 0.434 to 0.876. Now 99% of the programs run correctly. Now 72% of the parts have an IoU of 0.85 or more.

Terms. IoU is the volume of the intersection divided by the volume of the union. An IoU of 1.0 means that the model part and the reference part are the same. A trace is a numbered plan for the part. A checkpoint is a saved copy of the model weights.

1Data: three sets, each approved by a test

  1. Approved traces (20%). This set has 52,000 samples. Each sample has a drawing, a plan, and the code. A second model made a part from the plan only. The test approved the plan if the part volume was within 5% of the reference volume. The plan goes into the model's <think> block during training.
  2. Filtered drawing set (20%). This set starts with 500,000 drawing-and-code pairs. We remove three types of bad samples:
    • Code that does not run. This is 21% of the set. This code taught the model to write chamfer and fillet commands that fail.
    • Drawings from the old renderer.
    • Drawings with dimensions that are not shown. This is 33% of the set. The model cannot read a dimension that the sheet does not show. These drawings taught the model to invent dimensions.
  3. Self-made data (60%). The best model writes code for the training drawings. The pipeline runs each program and measures the IoU against the reference part. The pipeline keeps a sample only if the IoU is 0.8 or more. The pipeline keeps 44% of the samples. Each kept sample also keeps the plan that the model wrote.

2Training: one procedure for each model

  • Train all the weights. This method gave 0.05 more IoU than LoRA on the same data.
  • Use FSDP2 on one node with eight H200 GPUs.
  • Keep the vision tower frozen. Training the vision tower did not help.
  • Use these values: sequence length 5120, effective batch 64, learning rate 6e-6 with a cosine schedule, 4,000 to 6,000 steps.
  • Keep only one checkpoint. The geometry test selects the checkpoint. The loss curve does not select the checkpoint.

Important: The validation loss does not show the geometry quality. In run e22, the loss decreased until the last step. But the IoU had its maximum 2,500 steps before the last step. Run the geometry test on each checkpoint. Select the checkpoint that makes the most correct parts.

3Geometry test: the only measurement of quality

The test uses 96 approved parts. The parts do not change between runs. The test does these steps for each checkpoint, without an operator:

  1. Make the code for each drawing.
  2. Run the code in an isolated process.
  3. Make a mesh from the STEP file.
  4. Measure the volume IoU against the reference mesh. This is the same measurement as the lab's agentic-mesh-to-cad tool.
  5. If the code fails, show the error to the model. Let the model write the code again. Do this two times at most.

A failed program gets an IoU of 0. The test does not use opinions.

4Serving: the inference procedure

This procedure gives the best results for the least cost. Do these steps for each request:

  1. Make one program with greedy decoding.
  2. If the program does not run, make a new program with sampling at temperature 0.7. Do this three times at most. Use the first program that runs.
  3. If no program runs, show the last error to the model. Let the model write the program one more time.

The procedure does not use the reference part. On the best model, the procedure increased the mean IoU from 0.795 to 0.876. The share of programs that run increased from 89% to 99%. Greedy decoding solved 85 of the 96 parts. Sampling solved 10 more parts. One part was not solved.
